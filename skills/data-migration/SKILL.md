# 数据迁移

数据迁移是**不可逆风险最高**的一类改动。默认假设：生产已有数据、服务不能停、必须能回滚。

## 1. 先评估

- 表规模、写入频率、是否有长事务。
- 这次变更能否**向前兼容**（旧代码 + 新结构能否共存）。
- 回滚需要什么：备份、反向脚本、还是只能前滚修复。

## 2. 分阶段策略（大表优先）

1. **加**：先加可空字段/新表，不动旧结构。
2. **双写**：新代码同时写新旧字段。
3. **回填**：分批迁移历史数据（限制批量、可中断、可重入）。
4. **双读校验**：对比新旧结果，确认一致。
5. **切读**：读新结构。
6. **清理**：确认稳定后再删旧字段（通常延后一个发布周期）。

## 3. 迁移脚本要求

- **幂等**：重复执行不产生重复数据。
- **分批**：按主键区间或时间片，避免长事务与锁表。
- **可中断**：记录进度，失败可从断点继续。
- **可观测**：输出处理条数、失败条数、耗时。
- **先在副本/测试库验证**。

## 4. 回滚

- 明确回滚触发条件（错误率、数据不一致、延迟）。
- 准备反向脚本或恢复备份的具体步骤。
- **删除数据前必须有备份**，并确认备份可恢复。

## 5. 输出

```text
变更：<结构/数据>
影响：<表、规模、锁风险>
阶段计划：<1..n>
脚本：<路径，幂等与分批说明>
验证：<校验查询、对比结果>
回滚方案：<步骤与触发条件>
```

## 红线

- 不在没有备份的情况下删除或覆盖数据。
- 不做一次性全表更新。
- 不在同一个发布里既改结构又删旧列。
- 不假设迁移一次就能成功；必须能重跑。
