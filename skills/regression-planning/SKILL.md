# 回归范围规划

确定一次改动需要重测哪些内容。当改动面广、测试资源有限时使用。

## 何时使用

- 大改动上线前
- 频繁发布需要取舍

## 步骤

1. 从改动点出发找调用链与数据影响
2. 按风险分级：必测、抽测、不测
3. 列出对应自动化用例
4. 记录未测部分与风险

## 规则

- 回归范围基于影响面而非时间
- 高风险必须自动化
- 未测部分要显式说明

## 红线

- 不因时间紧跳过关键回归
- 不只跑新增用例
