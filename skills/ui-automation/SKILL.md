# 界面自动化

原则：**读状态 → 执行一个动作 → 重新读状态**。不要凭上一次的索引连续操作。

## 核心循环

```text
1. 列出应用/窗口 → 选定目标
2. 读取可访问性树（含元素索引与角色）
3. 执行一个语义动作
4. 用返回的或重新读取的状态确认结果
5. 再从新状态取下一个索引
```

**元素索引是短命的。** 延时、导航、焦点变化、滚动、窗口变化、界面重绘都会让它失效。每次动作后重新取。

## 选择器优先级

1. **稳定的应用标识**（包名/bundle id）> 名称 > 进程 id。
2. 多窗口时先列窗口，选定后用**同一个窗口选择器**贯穿后续调用，直到目标窗口改变。
3. 不凭元素总数推断有效索引；索引可能稀疏。以树里实际出现的为准。

## 动作选择（优先语义，其次坐标）

| 目标 | 首选 | 说明 |
| --- | --- | --- |
| 填文本框 | 直接设置值 | 可被校验的写入，优先于"点击+输入" |
| 按钮/开关 | 点击元素 | 用索引，不用坐标 |
| 列表项操作 | 元素次级动作 | 只用列表里列出的动作名 |
| 单键/导航 | 按键 | Return、Escape、Tab、方向键 |
| 组合键 | 热键 | 一个修饰键 + 一个键 |
| 兜底 | 坐标点击 | 仅在无元素可定位时使用 |

**修饰键点击要作为一个整体动作**，不要先按下修饰键再点、再松开——中断会让修饰键停留在按下状态。

## 验证

- 任何改变界面的动作之后，先取新状态再继续。
- 合成键盘输入**不保证已落地**：检查返回状态里是否真的出现了文本。
- 动作"成功"但界面没变化时：刷新状态 → 换更语义化的动作 → 必要时聚焦/恢复窗口。

## 坐标与截图

- 坐标是**窗口内坐标**，来自最新截图/状态。
- 截图带缩放比例时先换算：`动作坐标 = 截图像素 / 缩放比例`。
- 有元素索引或元素框时，优先用它们；元素框取中心点。
- 截图可能被其他窗口遮挡；无法前置窗口时，**以可访问性树为准**。

## 敏感输入

- 密码、令牌等通过标准输入传递，不要放进命令行参数（会进入 shell 历史与进程列表）。
- 除非用户明确要求，不要在界面里操作密钥类内容。

## 红线

- 不连续用过期索引批量点击。
- 不用"应该点到了"代替状态确认。
- 不在未确认焦点时假设键盘输入生效。
- 不做不可逆操作（删除、支付、发送）前不确认目标对象。

## 输出

```text
操作：<应用/窗口 + 动作>
结果：<状态证据>
截图/树：<关键片段>
未验证项：<如合成输入是否落地>
```
