# 一次性执行环境

目标：**每个任务一个干净环境，用完即弃**。环境本身不是资产，可复现的构建步骤才是。

## 三阶段模型

```text
1. 基础快照：装好系统依赖与工具链
2. 认证快照：在基础快照上完成登录，单独保存
3. 任务实例：从认证快照启动，供单次任务使用
```

**凭据绝不进入基础快照。** 认证单独成层，便于轮换与撤销。

## 1. 基础快照

- 只装必需项：语言运行时、包管理器、构建工具、代码检查工具。
- 克隆代码用**短生命周期的令牌**，不要把令牌写进配置或快照。
- 装完做一次冒烟检查：工具版本、构建能否通过。
- 记录：快照 ID、仓库地址与版本、项目根目录、暴露端口、超时设置。

## 2. 认证快照

- 需要用户交互的登录**必须由用户本人完成**，执行者没有交互终端。
- 无头环境用**设备码/一次性码**流程；普通回调式登录会绑定本机回环端口，在远端会挂起。
- 验证登录状态**优先用命令退出码**；必须匹配文本时先合并标准错误输出，并匹配完整的成功行。
  > 陷阱：`grep -i "logged in"` 会同时命中 "not logged in"。
- 未确认登录成功前**不要生成快照**。

## 3. 任务实例

- 从认证快照启动，一个任务一个实例。
- 名称带任务标识，长度受限并做字符清洗。
- 暴露端口要显式声明，避免与其他实例冲突。
- 结束即销毁；异常路径也要清理（用 trap / finally）。

## 状态管理

- 用一个状态文件记录快照 ID、源快照 ID、项目信息、端口，供后续阶段读取。
- 变量解析顺序：环境变量 → 状态文件 → 默认值。
- 快照 ID 解析失败就停下并报告，不要用空值继续启动。

## 清理

- 成功、失败、中断三条路径都要销毁实例。
- 长期保留的快照要标注用途与过期时间。
- 定期清理孤儿实例，避免资源泄漏。

## 红线

- 不在快照里保存明文凭据或长期令牌。
- 不复用上一个任务的环境跑下一个任务。
- 不在未确认登录成功时制作认证快照。
