# 配置管理

配置错误的典型表现是**静默地用错值继续跑**。目标：错误配置必须**启动即失败**。

## 1. 配置分类

| 类型 | 例子 | 存放 |
| --- | --- | --- |
| 代码常量 | 业务规则阈值 | 代码内，可审查 |
| 环境配置 | 端口、地址、开关 | 环境变量/配置文件 |
| 密钥 | 令牌、私钥 | 密钥管理，绝不进仓库 |

## 2. 优先级要显式

定义并记录解析顺序，例如：

```text
命令行参数 > 环境变量 > 配置文件 > 内置默认值
```

- 优先级必须**写进文档**，否则排障时没人知道生效的是哪个。
- 生效值要能在启动日志里看到（**脱敏后**）。

## 3. 启动时校验

- 必填项缺失 → **启动失败**，不要用空字符串硬跑。
- 类型与范围校验（端口 1-65535、超时为正数、枚举值在白名单内）。
- 互斥/依赖关系校验（选了 A 就必须提供 B）。
- 校验失败的错误信息要指出**具体变量名与期望**。

## 4. 默认值

- 生产必须显式配置的项，**不要给危险默认值**（如默认关闭鉴权、默认连本地库）。
- 默认值要安全且可预期；对"忘记配置"要能察觉。
- 每个环境维护自己的配置清单，避免"测试能跑、生产少一项"。

## 5. 密钥

- 只从密钥管理或环境注入；**不进仓库、不进日志、不进 URL**。
- 错误信息与堆栈要过滤密钥。
- 支持轮换：不把密钥硬编码进需要重新构建的地方。

## 6. 变更与排查

- 配置变更走与代码相同的审查流程。
- 提供"打印当前生效配置（脱敏）"的能力。
- 排查环境差异时，先 diff 两边的配置清单，而不是猜。

## 自检

```text
[ ] 缺失必填项时是否启动失败？
[ ] 启动日志能否看到生效配置（脱敏）？
[ ] 优先级是否写进文档？
[ ] 是否所有环境都有配置清单并可对比？
[ ] 密钥是否可能出现在日志/错误/URL 中？
```

## 红线

- 不给安全相关项危险的默认值。
- 不用空值/空字符串代替"未配置"。
- 不把密钥写进代码、镜像或仓库。
