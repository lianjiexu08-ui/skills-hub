# 设备自动化

移动端验证的关键差异：**坐标是归一化的、设备可能有多台、界面状态变化快。**

## 前置检查

- 目标设备是否已连接/启动？列出可用设备，确认唯一目标。
- 应用是否已安装、是否是需要重新启动的版本。
- 需要的权限（相机、定位、通知）是否已配置。

## 操作规则

### 坐标
- 一律使用 **0..1 归一化坐标**（左上角为原点），不要用像素。
- 不同分辨率设备共用同一套坐标。

### 点击
- 单击优先用**点按**，不要用"手势开始/移动/结束"拼一个单击。
  分离的按下与抬起在传输延迟下容易被识别为长按。

### 定位元素
- 优先读可访问性树，用元素的归一化框中心点：`x + 宽/2`，`y + 高/2`。
- 树可能被截断（节点数上限），超出时用截图辅助。

### 文本输入
- 确认输入框已获得焦点再输入。
- 注意键盘布局限制（部分实现只支持 ASCII）；不支持时会有明确报错，不要静默丢弃。

### 权限与硬件
- 权限授予/撤销/重置是独立操作，做完要重启相关能力或应用。
- 相机、位置等注入常常需要**重新启动目标应用**才生效。
- 硬件按键（返回、主页、锁屏、旋转）用专用动作，不要用坐标模拟。

## 多设备与清理

- 每台设备有独立的"活动"状态；多设备时**显式指定目标**，不要依赖默认。
- 用完主动停止/解绑设备流，不要留给下一次运行。
- 设备工具底层常依赖版本敏感的系统接口；升级系统后先重跑一次冒烟验证。

## 验证方式

- 每个操作后取新状态或截图确认，而不是连续盲操作。
- 关键路径至少覆盖：首次启动、权限拒绝、返回/恢复、旋转（如支持）。
- 断言用可访问性标签或界面文本，不用像素比对。

## 输出

```text
设备：<名称/标识>
应用与版本：<...>
步骤与结果：<操作 → 观察到什么>
截图：<路径>
未覆盖：<设备/系统版本差异>
```
