# 交接说明

读者**没有你的上下文**。判断标准：对方照着你写的内容，能直接继续，不需要再问你。

## 结构

```markdown
## 目标
<要做到什么，验收标准是什么>

## 已完成
<按条目列出，每条附证据：文件、命令结果、产物位置>

## 关键决定
<做过哪些选择，为什么；避免后来者重复讨论>

## 当前状态
<进行到哪一步；哪些已生效，哪些未提交/未部署>

## 下一步
<具体动作，按顺序；标注依赖>

## 阻塞与风险
<卡在哪里、需要谁决定、已知坑>

## 别做什么
<已经排除的方案及原因，避免重走弯路>
```

## 原则

- **状态要精确**：区分"已提交 / 已部署 / 仅本地修改 / 未验证"。
- **证据可查**：给路径、命令、输出摘要，而不是"已经处理好了"。
- **决定带理由**：只写结论会让后来者推翻重来。
- **下一步可执行**：写动作，不写"继续推进"。
- **不假设对方知道背景**：必要术语给一句解释。

## 反模式

- 交接内容只有一句"基本做完了，剩下收尾"。
- 不说明哪些改动未提交、哪些依赖未安装。
- 不记录已排除方案，导致后来者重复试错。
- 把"计划"写成"已完成"。
