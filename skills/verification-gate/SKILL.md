# 验证门禁

**没有证据的"完成"不算完成。** 本 Skill 负责用规则跑出证据，而不是让模型自评。

## 1. 探测项目类型

按仓库根目录的标志文件判断，可能同时命中多种：

| 标志 | 生态 | 常见验证命令 |
| --- | --- | --- |
| `package.json` | Node | 读 `scripts` 里的 `test` / `lint` / `typecheck` / `build` |
| `pyproject.toml` / `setup.py` | Python | `pytest`、`ruff`、`mypy` |
| `go.mod` | Go | `go test ./...`、`go vet ./...`、`go build ./...` |
| `pom.xml` / `build.gradle` | JVM | `mvn test` / `gradle test` |
| `Cargo.toml` | Rust | `cargo test`、`cargo clippy`、`cargo build` |
| `Makefile` | 任意 | 读 `make help` 或目标列表，优先用项目自带目标 |

**优先级：项目自带脚本 > 生态默认命令。** 项目已有约定就不要另造。

## 2. 按改动范围选择检查

不必每次都全量跑。按改动选择最小充分集合：

- 只改文档：跳过编译型检查，做链接/格式检查（如项目有）。
- 改单个模块：先跑该模块的测试，再跑类型检查。
- 改公共接口/依赖/构建配置：跑全量测试 + 构建。
- 改样式：跑 lint + 相关快照测试。

## 3. 执行与记录

对每条命令记录：

```text
命令：<完整命令>
结果：通过 / 失败 / 跳过
输出摘要：<失败时的关键错误>
退出码：<code>
```

- 失败时保存**关键错误片段**，不要只写"失败"。
- 超时或环境缺失要如实标注"未验证"，不能算通过。
- 顺序：类型检查/lint（快）→ 单元测试 → 构建（慢），尽早失败。

## 4. 判定

| 情况 | 结论 |
| --- | --- |
| 所有必跑项通过 | 可交付（附证据） |
| 有失败项 | 不可交付，进入缺陷修复 |
| 有关键项未跑（环境缺失/超时） | 待验证，明确说明缺什么 |

## 红线

- **没执行的命令不能写成通过。**
- 不得为了让检查通过而跳过用例、放宽断言、关闭 lint 规则。
- 不得用"本地能跑"替代实际执行结果。
- 验证证据要能被他人用同样命令复现。
