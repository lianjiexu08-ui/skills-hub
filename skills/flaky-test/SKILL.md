# 不稳定测试

**重试是掩盖，不是修复。** 不稳定测试会训练团队忽略失败，这才是最大成本。

## 1. 确认它真的不稳定

- 连续跑多次（如 20 次），记录失败率。
- 单独跑 vs 全量跑：只在全量失败 → 共享状态问题。
- 本地 vs CI：只在 CI 失败 → 环境差异。
- 记录失败时的具体断言与随机种子。

## 2. 按类别定位

| 类别 | 特征 | 常见原因 |
| --- | --- | --- |
| 时间 | 只在整点/跨天/时区变化时失败 | 用了真实时钟、时区未固定 |
| 随机 | 失败率不稳、换了种子就过 | 未固定随机种子、依赖 Map/Set 顺序 |
| 并发 | 并行时失败、串行时通过 | 共享可变状态、端口/文件冲突 |
| 顺序 | 单独过、组合失败 | 测试间依赖执行顺序或残留数据 |
| 网络 | 偶发超时 | 真实网络调用、未 mock |
| 异步 | 偶发断言过早 | 用 sleep 等待而非等待条件 |
| 资源 | 跑一段时间后失败 | 未关闭连接/文件、内存累积 |

## 3. 修复方向

**优先让测试确定化：**

- 注入可控时钟，不用真实 `now()`。
- 固定随机种子；避免依赖无序集合的迭代顺序。
- 每个测试独立准备与清理数据，不共享可变状态。
- 等待**条件成立**（轮询断言）而不是固定 `sleep`。
- 用唯一临时目录/端口，避免并行冲突。
- 外部依赖用可控替身；确需真实调用时加宽松超时并标记为集成测试。

**不要**：

- 加大 `sleep` 时间（只是降低概率）。
- 加重试直到通过。
- 把断言改弱到永远成立。

## 4. 隔离策略（临时）

确实无法立即修复时：

- 单独标记并在 CI 中**可见地**跳过（不要静默忽略）。
- 建立跟踪项：负责人、原因、期限。
- 设上限：隔离用例数量要有配额，避免越积越多。

## 5. 输出

```text
现象：<失败率、触发条件>
分类：<时间/随机/并发/顺序/网络/异步/资源>
根因：<证据>
修复：<改了什么使其确定化>
验证：<连续运行次数与结果>
```

## 红线

- 不用重试让测试变绿。
- 不静默跳过失败用例。
- 不用更长的 sleep 代替条件等待。
