# 持续集成流水线

目标：**尽早失败、结果可复现、失败原因一眼可见。**

## 1. 阶段设计

按"快 → 慢"排列，让廉价检查先拦住问题：

```text
1. 静态检查（格式、lint、类型）  秒级
2. 单元测试                     分钟级
3. 构建/打包
4. 集成测试
5. 端到端（关键路径）            最慢，可并行或按需
6. 安全/依赖扫描
```

规则：

- 每个阶段独立可读，失败时明确指向哪一步。
- 任一阶段失败即停止后续阶段（除非是独立的信息性检查）。
- 慢阶段并行化，但不要为了并行把有依赖的步骤拆开。

## 2. 可复现性

- 依赖用**锁文件**安装，不用浮动版本。
- 运行环境（镜像/运行时版本）**固定版本**，不用 `latest`。
- 环境变量与密钥通过 CI 的密钥机制注入，不写进仓库。
- 缓存要按锁文件哈希设键，避免用过期缓存掩盖问题。

## 3. "本地通过、CI 失败"排查清单

- [ ] 运行时/依赖版本差异
- [ ] 环境变量缺失或默认值不同
- [ ] 文件系统大小写敏感（macOS vs Linux）
- [ ] 时区与语言环境
- [ ] 并行度不同导致共享资源冲突
- [ ] 未提交的文件（本地存在、CI 不存在）
- [ ] 全局安装的工具本地有、CI 没有
- [ ] 网络访问限制（CI 无外网）

逐项对比，不要重复重跑流水线期待自愈。

## 4. 优化耗时

- 先测量：每个阶段的耗时与排队时间。
- 优先做缓存（依赖、构建产物）与并行。
- 把非阻塞检查（如全量端到端）改成按需或夜间跑。
- 不要为了速度跳过关键检查。

## 5. 失败可读性

- 失败日志要包含：哪一步、哪条命令、关键错误片段。
- 保存必要产物（测试报告、构建日志）并设保留期。
- 不稳定用例按专门流程处理，不靠重跑。

## 红线

- 不在 CI 里使用未固定版本的依赖或镜像。
- 不把密钥写进流水线配置或日志。
- 不用"重跑一次"当作修复。
- 不静默跳过失败检查。
