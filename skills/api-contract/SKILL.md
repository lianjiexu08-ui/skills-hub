# 接口契约

接口一旦被外部依赖，改动成本远高于实现成本。**先定契约，再写实现。**

## 1. 明确契约要素

```text
名称：<操作名>
方法/入口：<HTTP 方法+路径 / 函数签名 / 事件名>
输入：<字段、类型、必填、约束、默认值>
输出：<成功结构>
错误：<错误码、含义、可重试性>
副作用：<是否幂等、是否写入、是否需要授权>
```

## 2. 设计原则

- **命名表达意图**：资源用名词，动作用明确动词。
- **输入严格校验**：类型、范围、长度、枚举；拒绝未知字段或明确忽略。
- **错误可编程**：稳定的错误码 + 人类可读信息，不要把堆栈暴露出去。
- **幂等性显式**：写操作说明是否需要幂等键。
- **分页/限流**：列表接口必须有上限。

## 3. 兼容性

| 改动 | 是否兼容 | 做法 |
| --- | --- | --- |
| 新增可选字段 | 是 | 直接加，客户端忽略未知字段 |
| 新增必填字段 | 否 | 先给默认值或分版本 |
| 删除/重命名字段 | 否 | 保留旧字段并标注弃用 |
| 收窄类型/枚举 | 否 | 先放宽校验，分阶段收紧 |
| 改变错误码语义 | 否 | 新增错误码，不复用旧码 |

破坏性变更必须：**分版本或加兼容层 + 通知调用方 + 给出迁移窗口**。

## 4. 文档与验证

- 契约写在代码旁（类型定义/注释/OpenAPI），避免文档漂移。
- 为契约写测试：成功、校验失败、权限失败、边界值。
- 契约变更同步更新使用方与测试。

## 输出

```text
契约：<上述结构>
兼容性：兼容 / 破坏（说明迁移方式）
受影响调用方：<列表>
验证：<测试用例>
```

## 红线

- 不悄悄改变已发布接口的行为。
- 不返回不一致的结构（同一字段有时是数组有时是对象）。
- 不把内部实现细节（表名、内部 ID 语义）暴露成契约。
