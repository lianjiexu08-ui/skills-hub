# 凭据处理

默认假设：**任何进入代码、日志、URL、命令行参数的密钥都已泄漏。**

## 1. 密钥放哪

| 允许 | 不允许 |
| --- | --- |
| 密钥管理服务 / 环境变量注入 | 源码、配置文件、镜像 |
| 部署平台的密钥存储 | 命令行参数、URL 查询串 |
| 本地开发用 `.env`（已忽略） | 提交进版本库的任何形式 |

`.env` 必须被版本控制忽略，并提交一份 `.env.example` 说明需要哪些键（不含真实值）。

## 2. 使用

- 通过标准输入或运行时注入传递，避免出现在进程列表与 shell 历史。
- 最小权限：一个密钥只做一件事，按环境分开。
- 支持轮换：不要把密钥固化到需要重新构建的产物里。
- 传输必须加密；不通过明文通道传递。

## 3. 输出与日志

- 日志、错误、堆栈、监控上报都要**过滤**密钥。
- 错误信息只说明"认证失败"，不回显密钥内容或其片段。
- 调试输出默认脱敏；需要时用显式开关且不可在生产开启。

## 4. 泄漏处置

发现密钥出现在仓库/日志/截图里：

1. **立即轮换**（吊销旧值），而不是只删文件——历史里仍有。
2. 评估影响：该密钥能访问什么、是否已被使用。
3. 清理：从代码、历史、构建产物、缓存中移除。
4. 加防回归：提交前扫描、CI 检查。

## 5. 自检清单

```text
[ ] 仓库里没有任何真实密钥？
[ ] .env 被忽略，且有 example 文件？
[ ] 日志与错误输出会过滤密钥？
[ ] 密钥不出现在 URL 与命令行参数中？
[ ] 每个密钥权限最小、按环境隔离？
[ ] 有轮换方案与泄漏处置流程？
```

## 红线

- 不把密钥写进代码、配置、注释、测试数据。
- 不在日志、错误、截图中输出密钥。
- 不用删除文件代替轮换。
- 不把"内网/只有自己用"当作可以不脱敏的理由。
