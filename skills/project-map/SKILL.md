# 项目地图

目标：**不读完所有源文件**，用最少阅读建立一张可行动的地图，让后续任务不再冷启动。

## 三步阅读法

### 1. 看轮廓

- 目录树（排除依赖、构建产物、版本库目录）。
- 构建与依赖文件：`package.json` / `go.mod` / `pom.xml` / `pyproject.toml` / `Cargo.toml`。
- README、贡献指南、docs。

得出：项目类型、技术栈、大致分层。

### 2. 看骨架

- 入口文件读全文（启动点、路由注册）。
- 接口/类型定义、配置文件。
- 每个顶层目录用**一句话**说明职责。

得出：程序从哪启动、请求与数据怎么流动、模块边界。

### 3. 跟一个真实例子走一遍

挑一个有代表性的功能或请求，从入口追到结束，串起"入口 → 处理 → 存储/输出"。

得出：一个真实操作在代码里怎么跑通。

## 必须记录的信息

- **启动命令**：怎么跑起来。
- **验证命令**：测试、类型检查、lint、构建的具体命令。
- **入口与核心模块**：路径 + 一句话职责。
- **约定与坑**：代码风格、目录约定、已知限制、TODO。
- **术语表**：至少 3 条项目特有概念。

## 输出与共享

- 写入团队共享上下文（键名 `project-map/<项目名>`，类型 `note`）。
- 路径、命令、模块名**必须与仓库逐字一致**，不编造；不确定的标"待确认"。
- 后续任务开工前先读这份地图，避免重复摸索；代码大改后更新同一键（带期望版本号防覆盖）。
