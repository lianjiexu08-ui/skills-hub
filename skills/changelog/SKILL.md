# 变更日志

维护面向使用者的变更日志。当发布新版本、需要说明行为变化与升级影响时使用。

## 何时使用

- 每个版本发布前
- 用户反馈“升级后行为变了”

## 步骤

1. 按版本倒序记录
2. 分类：新增 / 变更 / 修复 / 移除 / 安全
3. 每条写清对使用者的影响与迁移动作
4. 标注破坏性变更

## 规则

- 写给使用者看，不写内部提交信息
- 破坏性变更必须给出迁移步骤
- 同一变更只记一次

## 红线

- 不把内部重构写成用户可见变更
- 不遗漏破坏性变更
