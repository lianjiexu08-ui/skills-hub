# 安全重构

重构的定义：**外部行为不变**。如果行为变了，那是功能改动，不是重构。

## 1. 前置条件

- 有覆盖当前行为的测试？没有就先补（见测试设计）。
- 明确"不变"的边界：公共接口、输出格式、错误语义、副作用顺序。
- 记录基线：改动前测试全绿。

## 2. 小步前进

每一步都满足：**改完能立刻验证，且可独立回滚**。

- 一次只做一种变换（提取函数 / 重命名 / 移动文件 / 替换实现）。
- 不混合重构与功能修改。
- 每步后跑相关测试。

## 3. 常用安全变换

| 目标 | 做法 |
| --- | --- |
| 去重复 | 先提取公共函数，保持调用点行为一致 |
| 拆长函数 | 按职责提取，保持参数与返回值语义不变 |
| 换实现 | 保留旧入口做适配层，切换后再移除 |
| 迁模块 | 先新增再改引用，最后删旧路径 |
| 重命名 | 用工具批量改引用，不手改遗漏 |

## 4. 兼容策略

- 破坏性变更先加兼容层（旧签名转发到新实现），标注弃用。
- 分阶段：新增 → 双写/双读 → 切流量 → 移除旧路径。
- 数据格式变化要有回滚方案。

## 5. 完成标准

- 相关测试全绿，且**没有放宽断言**。
- 公共行为无变化（接口、输出、错误、顺序）。
- 改动可被审查：每步有清晰意图。

## 输出

```text
重构范围：<...>
不变量：<哪些行为必须保持不变>
步骤：<1..n，每步的验证方式>
验证结果：<命令 + 结果>
风险：<...>
```

## 红线

- 不在重构中顺手改功能。
- 不为了"更优雅"大范围重写。
- 不在无测试保护时做大结构调整。
