# 前端问题排查

固定顺序：**复现 → 控制台 → 网络 → 状态 → 样式**。跳步会浪费大量时间。

## 1. 稳定复现

- 记录：页面路径、操作步骤、浏览器与版本、是否登录、是否特定数据。
- 区分：首次访问失败 vs 交互后失败（缓存/状态相关）。
- 试无痕窗口：能复现 → 排除扩展与缓存；不能 → 怀疑缓存/扩展/旧版本资源。

## 2. 控制台

- 有无脚本异常？看**第一条**错误，后续常是连锁反应。
- 有无资源 404、CSP 拦截、混合内容（HTTPS 页面加载 HTTP 资源）。
- 框架警告（key 重复、hydration 不匹配、弃用 API）常是隐性 bug 来源。

## 3. 网络

- 失败请求看：状态码、响应体、请求头（鉴权、内容类型）。
- 对比成功与失败请求的差异（参数、头、时序）。
- 检查是否重复请求 / 请求竞态（后发先至覆盖状态）。
- 检查缓存：`304`、Service Worker 返回旧资源、CDN 缓存。
- 跨域问题看预检请求（OPTIONS）与响应头。

## 4. 状态

- 数据是否真的到了组件？打印或查看状态快照。
- 是否把"加载中/空/错误"三种状态混为一谈（常见白屏原因）。
- 表单值是否被非受控/受控混用覆盖。
- 路由参数变化后是否重新取数。

## 5. 样式

- 元素是否在 DOM 但不可见（尺寸为 0、`display:none`、被遮挡、z-index）。
- 用开发者工具确认**实际生效**的样式，而不是源码里写的。
- 响应式问题限定在特定断点/缩放比例。

## 6. 验证修复

- 用**同一浏览器、同一路径、同一步骤**复现验证。
- 覆盖：首次加载、刷新、返回上一页、慢网络。
- 确认没有引入新的控制台警告。

## 输出

```text
现象：<表现>
层级：<控制台 / 网络 / 状态 / 样式>
证据：<错误信息、请求、状态>
根因：<...>
修复与验证：<...>
```

## 红线

- 不只凭截图猜原因。
- 不忽略第一条错误直接改后面的现象。
- 不用"清缓存再试试"作为结论。
