# 外部集成排查

对接问题几乎总能归到固定几层。**按层排除，不要一路猜。**

## 1. 先分层

```text
DNS / 网络 → TLS → 认证 → 授权 → 请求格式 → 服务端处理 → 响应解析 → 回调
```

从哪一层开始？看错误码：

| 现象 | 优先怀疑 |
| --- | --- |
| 连接超时 / 无法解析 | DNS、网络、代理、防火墙 |
| TLS / 证书错误 | 证书链、过期、自签、SNI |
| 401 | 密钥错误、过期、环境用错（测试/生产混用） |
| 403 | 权限范围不足、IP 白名单、账号状态 |
| 404 | 路径版本、资源 ID、环境 |
| 429 | 限流；检查重试策略是否放大问题 |
| 5xx | 对方故障；确认是否可重试（幂等性） |
| 200 但数据不对 | 响应结构变更、字段类型、编码 |

## 2. 抓一次真实请求

- 记录：完整 URL（脱敏）、方法、关键头、请求体（脱敏）、响应状态与体。
- 用最小可复现请求验证（curl / SDK 最小示例），排除业务代码干扰。
- 对比「能通的调用」与「不能通的调用」的差异：环境、头、时间戳、签名基串。

## 3. 常见陷阱

- **时间偏差**：签名、JWT、TOTP 对时钟敏感；检查本机时间同步。
- **签名基串**：参数排序、编码方式、是否包含空值、换行符。
- **环境串用**：测试密钥打生产、生产回调地址指向测试。
- **重试放大**：非幂等接口 + 自动重试 = 重复创建/重复扣款。重试必须配幂等键。
- **回调**：地址不可公网访问、证书不被信任、响应超时导致对方重投、重投未去重。
- **编码**：`+` 与空格、URL 双重编码、非 UTF-8 字符。
- **SDK 隐式行为**：自动重试、自动解压、超时默认值。

## 4. 验证修复

- 用**同一条最小请求**验证，而不是"再点一次界面"。
- 验证幂等：重复调用不产生重复副作用。
- 验证失败路径：对方返回错误时本地状态不留脏数据。

## 输出

```text
层级定位：<在哪一层>
证据：<请求/响应/错误码>
差异对比：<能通 vs 不能通>
修复：<改了什么>
验证：<最小请求结果 + 幂等性>
```

## 红线

- 不把密钥、令牌贴进对话或日志。
- 不在未确认幂等性时加自动重试。
- 不用"重试几次就好了"作为结论。
