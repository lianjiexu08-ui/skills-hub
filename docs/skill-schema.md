# SKILL.md 编写规范

## 文件结构

```text
skills/<skill-id>/SKILL.md      必需
skills/<skill-id>/reference/*.md  可选：按需加载的详细步骤
```

`skill-id` 必须符合 `^[a-z0-9]+(?:-[a-z0-9]+)*$`，且与 frontmatter 的 `name` 完全一致。

## Frontmatter

```yaml
---
name: skill-id
description: 一句话说明用途，并列出触发场景的关键词。
---
```

| 字段 | 必需 | 要求 |
| --- | --- | --- |
| `name` | 是 | 与目录名一致，小写加连字符 |
| `description` | 是 | 说明"做什么"+"什么时候用"，包含触发关键词 |

## 正文要求

1. **先说何时用、何时不用**：避免被错误触发。
2. **流程可执行**：步骤有明确的输入和产出，不写空泛原则。
3. **规则优先于模型判断**：能用命令、检查、正则判定的，不依赖模型"感觉"。
4. **写明验证方式**：怎么确认这一步真的完成了。
5. **标注边界**：没跑的检查不得声称通过；不确定的标"待确认"。

## 禁止

- 写死某个产品/平台专属的命令或路径。
- 包含密钥、令牌、内网地址、个人信息。
- 承诺"一定成功"或鼓励跳过测试、注释掉失败用例。
- 大段复制外部文档；需要细节时用 `reference/` 分文件，按需读取。

## 长度

单个 `SKILL.md` 建议 60–150 行。超过 150 行时，把分阶段细节拆到 `reference/`，主文件只保留决策与索引。
