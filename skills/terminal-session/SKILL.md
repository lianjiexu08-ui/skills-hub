# 终端会话驱动

交互式会话不是无状态 API：**输入时机、就绪状态、输出分页**都会让自动化失败。

## 1. 基本循环

```text
1. 列出会话 / 确认目标句柄
2. 读取当前输出，判断处于什么状态
3. 发送输入
4. 等待明确的就绪信号（不是固定睡眠）
5. 读取结果
```

**发送前先读。** 不知道当前状态就发输入，等于盲打。

## 2. 等待就绪，不要盲等

- 优先等待**语义状态**（空闲提示符、TUI 就绪、进程退出），而不是 `sleep`。
- 等待必须带**超时**；超时后如实报告"未就绪"，不要继续发送。
- 长任务用"是否产生新输出/是否回到提示符"判断，而不是猜耗时。

## 3. 句柄生命周期

- 会话句柄是**运行时作用域**的，进程重启或界面变化后可能失效。
- 句柄失效时：重新列会话 → 用**新的**句柄继续。
- **绝不向旧句柄和新句柄同时发送**，会出现重复执行。
- 一个任务只保留一个权威句柄，避免"我以为发给了 A，其实发给了 B"。

## 4. 长输出

- 一次性读取有上限，超出会被截断。
- 用游标分页：先读尾部预览 → 从**最早未读**位置开始翻 → 按返回的下一页游标继续，直到没有更多。
- 不要只依赖最后 N 行做判断（关键错误常在被截掉的中间）。

## 5. 创建会话

- 优先让创建动作**直接启动目标程序**，而不是"先开一个空 shell 再手动启动"——后者容易留下孤儿空会话。
- 若必须两步，先确认空会话确实空闲，再在其上启动。
- 已有环境里需要新会话时，在当前工作区新建，不要为此再建一个工作树。

## 6. 结束

- 主动停止自己启动的会话；不依赖进程退出时自动清理。
- 停止前确认没有未保存的交互状态。

## 输出

```text
会话：<句柄/名称>
状态：<就绪 / 忙碌 / 已退出>
发送：<输入摘要>
观察到：<关键输出片段>
未确认：<是否真的生效>
```

## 红线

- 不用固定睡眠代替就绪检测。
- 不在句柄失效后继续用旧句柄。
- 不同时向新旧句柄发送。
- 不只读末尾就断言"没有错误"。
